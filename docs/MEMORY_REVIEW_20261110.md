# 从学习来源到可确认的慢记忆

3D Demo 已增加“学习记忆 → 从本次学习中，挑选值得留下的线索”。用户明确发起后，由 Kimi 在后台整理当前活动的来源；页面展示摘要、适用范围、保留理由和原句，可逐条选择“保留到学习记忆”或“本次不保留”。未经确认的候选不会自动写入慢记忆。已有的更正、忘记和来源解释继续可用。

本片没有开启全局自动整理或自动提升策略，也不改变普通聊天和明确保存讲解偏好的入口。

## 核心实现

- 独立 Store、工作台协调及 UI 模块；复用既有来源版本、预算、租约、LLM worker 和教育类别条件。一次最多整理 12 条最早未覆盖来源，只 claim 指定任务，不消费其他档案的队列。
- 保留动作重新核验来源、会话、活动、版本与类别条件。重要性理由不提高来源可信度；临时范围、未接受计划、错误来源类型等仍不能提升。已明确保存的偏好不会再次生成重复副本。
- 前台操作让后台让步；取消信号覆盖任务尚未首次运行的时刻。中断后只在明确继续时再执行，不自动重试模型。过期任务回收保留尝试历史和原有预算。
- 最早的待处理任务优先展示，后来排队的批次不能遮住正在处理或待确认的批次。折叠组件停止来源读取；展开且有运行任务时每 2 秒观察状态。新档案或版本拒绝迟到结果。
- “本次不保留”针对该摘要，不删除原始学习记录。同一来源快照不会借重复操作重置预算；新的学习上下文仍可重新理解有效来源。忘记已保存记忆继续使用既有来源失效机制。

## 一次真实 Kimi 整理

通过公开比较记录接口创建独立“学习线索 · Demo”模拟案例：A 在 30cm 处静止读得 30cm，只读一次、未让小车行驶；B 的 50cm 测试明确接受但尚未实施。随后从真实网页发起一次整理。

实际 **1 次 Kimi 调用，0 重试**，生成 2 条 shadow 候选；确认前慢记忆为 **0**。ACP 回执确认完整结果、owned 进程和目录正常清理；从 owned 进程启动后的完整校验时间为 19.141 秒，不能当作浏览器时延或 P95。

观察候选忠实保留单次、静止、未行驶、硬件未核验及不能比较两个位置的限制，人工核对后保留为 1 条 `reported_progress`，来源等级仍是模拟。计划候选同时引用计划与观察背景；虽然计划本身已接受，仍未满足该类别的全部来源均为已接受计划这一条件。因此保留按钮被禁用，随后选择“本次不保留”。**该模型输出没有完全通过提升条件，原件与拒绝原因保留。** 后续应改进计划和观察的摘要拆分，不把 `all` 放宽成 `any` 来制造通过。

两项决定的精确重放均无重复记忆或新模型调用，快状态保持不变，没有把计划记成完成。第一次交付观察器误用了未维护的工作台级 consolidation 计数而失败；原脚本与失败记录保留，后续改读真实 Kimi provider 计数及对应 ACP job 回执。没有改产品指标或重跑模型。
