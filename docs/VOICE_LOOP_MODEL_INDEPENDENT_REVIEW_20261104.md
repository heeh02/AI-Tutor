# 固定合成语音的真实自动轮换：独立产物审阅

本次审阅支持 `voice-loop-model-first` 在既定范围内通过：中文、英文各一个 Workstation，各连续完成两轮，共 4 次真实 Zipformer 转写、4 次真实 Kimi 请求和 7 段真实 Qwen/CPAL 输出。每种语言第二轮都经生产 rearm 后重新开启合成输入源，未直接赋予循环 phase 或伪造播放完成。审阅是知晓方法的代理复核，审阅者也参与诊断实现；不是独立人类或盲评。

原始报告为 `runtime/goal-baselines/20261104/voice-loop-model-first/report.json`；逐项复核结果及原产物哈希保存在同目录新建的 `independent-review-backend.json`。95 项产物一致性检查通过，检查内容包括子报告、独立 round 文件、方法和实测源码哈希、转写与唯一用户 turn、输入关闭与来源 join、播放身份、重新就绪和自有进程清理。这些是产物检查数，不是新增运行测试数。原始产物未改动。

两种语言的转写仅与固定源在标点、大小写上不同，实际原文未经补写就提交教学。每轮恰有一个对应 request 的用户 turn；重复 Start、Stop、Send 均在执行的诊断中被拒绝，输出期间再次 Start 也被拒绝且没有多开输入。每种语言的录音 token 为 1、3，会话提交 generation 为 3、6，同一 session 和 loop epoch 保持一致。

四个输入源均在真实 capture owner 发布 `input_closed=true` 前停止并 join 采样线程，终态为真实 Sonora `speech_end`。输入是按 20 ms 节奏送入的固定合成成人语音 WAV，附带已声明的 4,000 ms 安静尾部；没有打开物理麦克风。捕获样本数与源发出样本、ASR 样本数一致；VAD 分析样本稍少于关闭期间保存的完整 PCM，不能将分析音频时长当作墙钟关闭时间。

7 段输出均有相同 playback ID、epoch 和 `qwen_pcm` 引擎的开始与完成回执，累计向原生回调提交 2,081,280 帧，均报告预测排空。四轮都在同一 Store 快照中观察到真实 `first_callback_submission` 已存在、而文本 final 尚未验证，支持“首段输出回调先于 final”的顺序判断。产物没有保留精确回调时间，不能推算重叠毫秒数或声学首音。rearm 计时也只是消费者观察到文本和输出完成后的冷却等待，不是设备延迟；每语言实际重开一次，最后一次 armed 不代表又进行了第三次采集。

模拟客户端按 400 ms 间隔维护 3,000 ms 租约，心跳任务正常结束，各轮均观察到 cooldown 后 armed，最终显式暂停。该运行没有测试失联、租约过期、浏览器隐藏或编辑草稿。显示 ACK 和心跳是模拟客户端行为，不是浏览器呈现验收。

两套诊断自有 ASR 实例均非强制退出，并确认 launcher、实际解释器退出及两个 Job 清空。Kimi 两个子运行均各 2 请求、0 重试、0 错误并清理完成。外层 Qwen 报告正常 owner stop、服务退出 0、bridge 退出 0、Linux 自有进程组清理确认，未强制停止。两语言使用两个顺序执行的子进程，Qwen 由外层 runner 持有；不能称为同一生产 main 托管所有服务。外层运行约 243.828 s，其中 Qwen ready 为 113.407 s；这不是 30 分钟持续负载。

生产候选提交路径实际运行在隔离 simulator 数据库：中英文 goal 均发生更新，英文 pending_step 也发生更新，reported_result 仍为空。不能说所有候选都仅处于 shadow；本审阅也不将链路完成等同教学或记忆语义质量通过。中文回复提出停止目标并询问连接模块，英文回复说明不能远程停车并要求使用已有安全停法和确认；没有把这条固定输入写成小车已经停止的物理事实。
