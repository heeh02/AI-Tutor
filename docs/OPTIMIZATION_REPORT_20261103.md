# AI Tutor 软件优化记录

日期：2026-11-03（Asia/Shanghai）。本轮先核对原始实现方案、执行要求、当前 Rust 架构、产品流程与分项验收，再审查当前源码。原始 Python/React 方案已被后续 Rust 决策取代，归档原型不属于本轮生产代码。

## 项目理解

产品面向功能积木 STEM 教学，围绕提出目标、搭建、报告试验、观察和修改形成学习闭环。当前应用负责教学指导、来源明确的快慢记忆、人工选择视觉目标、本地语音，以及教师工作台。学习者档案与视觉目标独立；真实与模拟记录独立；历史配置不能直接当作当前硬件事实。

生产实现由 Rust/Tokio/Axum、Yew/WebAssembly、SQLite、原生视觉与语音管线组成。教学文字经已有 Kimi CLI 发送到远程模型，图像与声音留在本地。源码和学习数据不对外发布。

## 已修复与优化

| 范围 | 触发问题 | 本轮处理 |
|---|---|---|
| 启动 | 无浏览器模式绕过已有实例检查；不同端口可启动同目录第二服务、覆盖唯一描述文件 | 统一复用检查，并以操作系统文件锁约束同目录单实例；崩溃后系统释放锁 |
| 本机请求 | 启动/停止等入口使用默认 HTTP 客户端，可能受代理或重定向影响 | 统一禁用代理和重定向，限制连接及请求时间，校验描述文件端口/凭证格式 |
| 教学投递 | 先确认显示、移除候选，再分步写记忆；中途失败留下部分状态且无法完整重试 | 显示确认、候选应用与来源更正置于同一事务，成功提交后才移除候选 |
| 存储 | COMMIT 失败后连接可能遗留事务；历史会话/轮次查询缺索引 | 提交失败回滚，增加 sessions/turns/events 查询索引；验证查询计划 |
| 录音隔离 | 迟到的停止或清理请求可能影响新录音 | 服务、CLI、UI 同步绑定会话及录音批次；丢弃使用原子代次检查 |
| 麦克风故障 | 输入流出错只记录错误，录音状态/部分样本继续保留 | 所属线程关闭流、清零缓存并退出录音；停止交接时再检查故障；旧回调不能污染新录音 |
| 界面草稿 | 旧发送失败回执覆盖后来输入的草稿 | 仅在当前输入为空时恢复失败文本，保留新编辑 |
| 界面并发 | 切档案、保存、发送等动作并发时旧回执被丢弃或界面读取旧状态 | 操作串行化并等待操作后的状态刷新；停止入口继续可用；过期记忆列表被拒绝 |
| 空闲预览 | 摄像头关闭或失败时仍以直播频率请求画面 | 关闭/失败间隔 1000ms，连接中 250ms，有效直播 33ms；响应完全相同时才跳过重绘 |
| 视觉状态 | 只读取状态/目标也深复制整块 JPEG | 分离元数据读取；状态和选目标不再复制图像；画面编码省去一次中间图像复制，保持同帧一致性 |

这些改动没有改变教学来源等级、选脸与档案分离规则、运动标定或云台保护门限。性能说明仅涉及实际代码路径与请求间隔，未把它们换算成未经测量的整机提速百分比。
