# 同源检测输入的追踪器对照结果

本轮继续使用生产 ByteTrack。固定合成测试中，OC-SORT 尚未显示足以支持替换的收益。没有操作摄像头、保存人脸或更改云台配置。

输入为同一份 16 场景、835 帧 JSONL：稳定单/多人、交叉、100–800ms 遮挡、低置信度、非线性移动、不规则时间戳与不同输入频率。SHA-256 为 `0a891752dbf9a2f81636a4912123d174c580b6b0e99d8bdd89c331c36b87dbe2`。生产 ByteTrack 和官方 OC-SORT default、OC-SORT + BYTE 的关联结果，均经过同一个 Rust 所选目标状态处理模块。

| 指标 | ByteTrack | OC-SORT | OC-SORT + BYTE |
| --- | ---: | ---: | ---: |
| 原始关联 ID 切换 | 5 | 5 | 5 |
| 所选目标错误绑定帧 | 0 | 0 | 0 |
| 选择被清除次数 | 4 | 4 | 4 |
| 正确所选目标可见帧 / 可见机会 | 622 / 684 | 614 / 684 | 621 / 684 |

三种路径在 100/300/500/600ms 遮挡后均以同 ID 在第一帧恢复。601ms 遮挡下原始关联可以保持 ID，但应用已按既定超过600ms保护清除选择；800ms下原始ID改变，应用同样不自动重绑。不能把这里的清除视为单纯算法错误，也不能仅以错绑为零忽略目标可用率。

ByteTrack 20 次内核更新重放的小样本 P95 为约 0.0017ms；官方 OC-SORT Python 路径 P95 约 0.8–1.1ms，含观测插桩并在共享宿主机运行。语言、运行时和插桩不同，不能将耗时差全部归因于算法。推理和图像编解码不在这个内核计时中。

官方参考代码固定版本、MIT许可证和逐文件哈希见 `vendor/ocsort-reference/provenance.json`。用于读取关联索引的内存插桩与未修改上游在1,670次帧更新上验证了公开输出、track ID、Kalman x/P逐元素相等；没有用简易 IOU 算法替代 OC-SORT。

全部原始数据和逐场景结果：`runtime/goal-baselines/20261104/tracker-compare/report.json`。复现命令见 `scripts/tracker-lab/README.md`。

这些是可复现的工程对照，不能证明真实人脸、姿态变化或真实遮挡下的准确率。后续重点是摄像头时间戳、显示延迟和联合负载的实测；真实场景有明确关联收益后，再评估独立 Rust OC-SORT 实现及其数值一致性。
