**后续接入进展：**Rust owner/client、录音终稿选择、UI 状态及可回退候选已完成；实际工作台生命周期、推理取消和ASR/TTS同卡共驻也已验证，见 [双模型共驻记录](QWEN_GPU_PAIR_20261106.md)及 [Rust 接入记录](QWEN_ASR_RUST_INTEGRATION_20261106.md)。以下保留本次模型质量实验的原始口径，安装版仍未切换。

## 同输入准确率

三种模型均完成同一份 1315 段原始 16 kHz PCM。下表错误率使用同样的 1279 条参考完整样本；36 条含未知参考的录音仍保留并独立报告。分数越低越好。

| 指标 | Zipformer | Paraformer | Qwen3-ASR-1.7B |
| --- | ---: | ---: | ---: |
| 中文 CER，679 条、4736 字符 | 11.95%（566 错） | 12.16%（576 错） | **7.09%（336 错）** |
| 英语 WER，242 条、1105 词 | 50.68%（560 错） | 47.51%（525 错） | **20.63%（228 错）** |
| 中英混说项目 MER，358 条、5260 单位 | 24.89%（1309 错） | 20.48%（1077 错） | **10.08%（530 错）** |
| 全部 1315 条的空终稿数 | 104 | 36 | **3** |

Qwen 全量运行 1315 次尝试、1315 个终稿，零失败、未运行、重试或截断，未合并任何预检结果。空串照常计入错误。原始语言标签只用于分层报告，没有提供给模型；没有热词、参考文本、提示调优、VAD 或 aligner。

固定短答切片同样改善：不超过 1 秒的 369 条参考完整录音，空终稿从 94 降到 3；英语 1–3 词的 130 条短回答，WER 从 73.33% 降到 32.89%。这些切片受先前错误分析启发且相互重叠，不是全新留出集。否定词切片的距离下降不等于否定语义全部保真，例如预检中的混语 `no我专业…` 仍被识别为 `那我专业…`。数字切片为空，不能据此宣称数字、单位识别通过。

数据仅含两名历史标注 24/25 岁的匿名成人，不能代表儿童、全年龄、课堂噪声或远场麦克风。

## 本机速度和显存

硬件为 RTX 5070，12227 MiB 显存。固定配置为 Transformers、BF16、SDPA、CUDA:0、batch=1、greedy、最多 512 个新 token。707 个参数张量均在 GPU，实际参数计数 2,038,052,480。未加载 vLLM。

| 全量运行指标 | 实测 |
| --- | ---: |
| 模型加载 | 14.158 秒 |
| 加载后首次识别 | 18.844 秒 |
| 后续 1314 次 SDK 调用 P50 / P95 | **227.84 / 542.48 ms** |
| 后续调用最大值 | 1082.33 ms |
| Torch allocator 峰值 allocated / reserved，含加载 | 4480.79 / 4516 MiB |
| 整卡 250 ms 抽样最高占用，包含桌面 | **6585 MiB** |

这些是完整波形已就绪后的离线 SDK 调用时间，包含模型前处理与解码，排除文件读取；不是松键到终稿、流式字幕或端到端教学响应。后续调用复用了进程内模型，磁盘编译缓存来自前序预检。P95 是该固定样本集的描述统计。模型加载与首次推理均须在应用声明 `warm_ready` 之前完成。

全量 outer 正常退出 0，GPU 监视器已退出，记录的 Linux PGID 317957 无残留进程。单模型显存验证不证明 ASR 与 TTS 共驻；现有 TTS 停止播音仍可能保留 GPU 模型，下一阶段需要真实联合测试。

## 实现与失败记录

- 模型固定到 `Qwen/Qwen3-ASR-1.7B` revision `7278e1e70fe206f11671096ffdd38061171dd6e5`，SDK 固定到 `QwenLM/Qwen3-ASR` commit `7c6daf77a2421100f5fb066495372c00129d39ff`。全量推理前重新核验全部模型文件及 PCM 哈希，逐条输入再次核验。
- 独立环境位于 `/mnt/c/Users/RBMS/.cache/ai-tutor-asr-17b-env-20261106`，torch 2.13.0+cu130、transformers 4.57.6、qwen-asr 0.0.6。没有改动现有 TTS 环境。
- 首次四条预检在第四次遇到 WSL 缓存盘 `ENOSPC`，前三条完成，整次保留失败；没有 OOM。独立环境等版本迁移、编译缓存转移后，第二次四条预检全部完成。全量是另一轮事先声明的 1315 次运行。
- SDK 会解析语言前缀并在默认阈值 20 下处理重复文本。评分使用 SDK 最终文本，另存未经该解析的 decoded chunks，不能把最终文本称为原始解码。SDK 及模型源码未修改。
- 三种推理管线不同：Zipformer 使用 600 ms 右侧上下文零样本，Paraformer 使用 660 ms 与 final 标记，Qwen 接收完整原波形。比较说明的是相同输入上的最终文本质量，不是流式性能等价。

## 下一步接入

独立终稿服务原型已通过 15 项 fake 核心测试，覆盖预热准入、取消后保持 busy、迟到结果丢弃、旧代次、超时、停止、空终稿和截断拒收。随后实际执行一次预热及四条固定 HTTP 转写：全部 200、身份匹配且文本逐字等于本次全量结果；请求到终稿分别 **452.23、411.56、357.51、141.39 ms**。这四条不能当作总体 P95。就绪需 70.917 秒，包含校验、导入、加载和预热；正常 Stop、服务与外层均 exit 0，无强制结束，PGID 326320/326321 均无残留。健康检查 200、错误实例 409、末尾 idle 200。

HTTP 首次尝试因测试客户端局部函数 `http` 遮蔽同名模块，在健康检查前失败，零转写、已完成一次预热，服务正常退出。原失败和源码完整保留；第二次只修正客户端函数名，另行声明一次预热和四请求预算，未改模型或服务。服务仍为独立原型，真实推理期间取消、Rust 客户端、应用录音、TTS 共驻均尚未验收。此原型依赖当前固定模型清单，生产打包时需迁入稳定资源路径。

保留现有快速 partial 字幕，新增独立 Qwen 离线终稿服务，Rust 在单一提交点选择一次最终文本。先验证 HTTP 身份、取消、新录音代次、超时和进程回收，再接 `AudioService`。GPU 推理不进入现有 20 ms 音频分块 ACK，也不持有请求状态锁。

取消后先使旧结果失效，仍在运行的推理继续占 busy，直到实际结束；不能把 HTTP 断开等同于 CUDA 停止。现有 `<450 ms / RMS<0.002` 录音过滤、真实麦克风短答、噪声、儿童、中英切换和 ASR/TTS 资源协调需单独验证。当前 PyTorch 路径没有官方 vLLM streaming API 的能力，不能宣称 Qwen 本身已提供实时字幕。
