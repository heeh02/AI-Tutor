# 语音打断误触发的有限离线诊断

结论：原纯回声失败已精确复现。配置切换没有修复该负例；同实例经过实际远端音频适应后表现不同，支持继续调查冷启动的近端人声判定。**本片没有修复或启用自动语音打断。**

## 方法与范围

新增仅在测试构建编译的 `audio/barge_diagnostic.rs`，使用既有作者编写的中文、英文 SAPI WAV，并验证原 SHA256。原 `barge_in` 阈值（0.60、20 帧中 12 帧）及失败测试保持不变。

四组配置为：原生产 Legacy/HP off、同配置加公开 echo statistics、官方默认 Legacy/HP on 加 statistics、Hmm/HP on 加 statistics。官方默认与显式 Legacy/HP on 是同一配置，不算两个独立策略。核心范围为纯回声、近端人声在 1/4 秒插入、两者混合；另有 40/160 ms 延迟和同波形不同 API 延迟的有限对照。两条诊断行先用实际远端音频运行同一个 AEC 10 秒，再建立起音检测；此等待仅用于研究，不是产品门槛。

共 30 行统计，固定冷启动对照仍从第 0 帧开始。起音一旦锁定就不重置，因此提前误触发不会被随后近端人声“覆盖为通过”。独立观测 VAD 在锁定后继续记录，仅作分析、不决定候选。

执行证据为 `runtime/goal-baselines/20261109/barge-diagnostic-next/first`，包括固定源码、日志、report 和 runner。结构诊断 exit0、用时 95.598 秒（含编译），测前后五份源文件哈希一致。它不表示 30 项语义验收通过。未打开设备、未启动模型、无云端调用，未保存 PCM。

## 实际观察

| 条件 | 结果 |
| --- | --- |
| 原生产配置、80 ms 波形/80 ms API 延迟、冷启动纯回声 | 第 38 个零基帧出现误候选（确认时刻 390 ms），与原失败一致 |
| 同配置增加公开统计 | 同样第 38 帧，原/处理后总能量也与对照相同 |
| 官方默认 HP on 或 Hmm/HP on，同一纯回声 | 第 35 帧误候选（360 ms）；没有修复 |
| 四配置、纯近端人声分别在 1/4 秒插入 | 均在插入后 240 ms 发现候选；包含固定 WAV 自身起始静音，不是声学人声起点延迟 |
| 四配置、80/80 混合 | 都先被远端回声误触发，不能计算有效近端接管延迟 |
| 同 80 ms 波形、API 延迟改为 0 的纯回声 | 四配置均未触发；这些行没有近端混合对照，不能据此把生产 API 延迟改为 0 |
| 原配置、40/40 与 160/160 | 纯回声未触发；4 秒插入的混合人声分别 370/380 ms 出现候选；仍是有限合成条件 |
| 同 AEC 先适应 10 秒，再监测原 80/80 纯回声 | 后续 10 秒监测没有候选 |
| 同 AEC 适应 10 秒，近端人声于 11 秒插入 | 插入后 240 ms 出现候选，未被早期回声抢先触发 |

原误触发帧已经有约 36.24 dB 的能量衰减，独立 VAD 概率仍为 0.8405；整段 10 秒衰减约 41.96 dB。因此“平均消回声量不错”不能证明起音判断正确。混合音频的能量比包含近端人声，不能称作纯回声抑制或失真分数。

非作者只读复核保存在同目录 `independent-review.json`，核对了五份冻结源码哈希及 30 行分类/计数。复核进一步指出：适应后的监测区间同时改变了远端语料相位，没有同相位 fresh-AEC 控制，不能唯一归因于适应，也不能推出 10 秒门槛；混合 `after_near` 统计还包含近端说完后的远端尾段，不能解释为近端人声衰减。四配置重复使用同一固定语料，不能当作独立人群样本。

开启公开统计的对应误触发帧，residual likelihood 约 0.02331、ERLE 约 0.1755 dB。低 likelihood 并未阻止本次误触发；原值不构成无回声证据。

## 已核对的原因与限制

依赖源码精确版本为 Sonora 0.2.0，七份来源哈希保存在 `dependency-source-audit.json`。浮点输入应为 `[-1,1]`，项目尺度正确；独立 VAD 分析副本乘 32768 也与其 FloatS16 用法一致。

`sonora-aec3/src/aec_state.rs` 要累计超过 0.4 秒有效且未饱和 render，并满足延迟或收敛条件，才允许线性滤波输出。第 38 帧确认最多 390 ms，必然尚未达到此前提；`echo_remover.rs` 此时选择原 capture 频谱，再进行非线性抑制。项目当前起音资格只有处理调用成功、参考身份/连续性有效，不能区分剩余远端人声与近端人声。

Legacy 透明模式至少需要超过 6 秒有效 render 才可能激活，不能解释此早期误触发。公开 residual detector 自身有慢启动可靠度，当前公开统计也没有可直接使用的 readiness/converged 字段；不能把低数值当成冷启动通行证。

API delay 表示设备/软件队列的两段时差，而非直接等于波形传播延迟。生产时间公式与依赖契约一致。上述 80/0 行只是口径对照，不证明原固定失败无效，也不授权绕过真实时间戳。公开实现参考：[Sonora](https://github.com/dignifiedquire/sonora)，本片裁决依赖已锁定的本地 0.2.0 源码及实测，未升级依赖。

## 下一步与当前交付

后续判定需要可置信的近端/残余回声信息，特别是冷启动、参考间断、重建滤波器之后；近端弱声不能为了去掉负例而被一并屏蔽。固定等待 400 ms/10 秒、调高 VAD 阈值、低 residual likelihood 或高平均衰减都尚不足以作为修复。
本轮停止配置切换路线，不新增任意生产门槛。原失败证据继续保留，自动打断默认关闭，现有 Demo 与已验 Destiny C# 语音桥继续使用显式识别、朗读和取消。
