# UI 基础优化：预览隔离与对话滚动

日期：2026-11-03。范围为 P0/P4 的 Rust/Yew 界面基础；没有操作浏览器、摄像头、麦克风、云台或真实学习数据。

## 修改前基线

- `App` 持有完整 JPEG/base64 帧、画面请求与定时器；每个改变的画面响应都会请求 `App` 重新渲染，涉及对话、教师表单和记忆面板。
- 同一个 `App::rendered` 同时负责滚动和显示确认。滚动条件仅为消息条数变化，后端最近 24 条窗口满后，新消息不会增加条数，因此不再触发跟随。
- `scroll_into_view` 作用于尾部元素，可能带动页面祖先滚动；未保存用户上翻阅读的意图。
- 上一轮软件验收是 workspace 261 项通过、UI 25 项通过。这里只引用历史基线，新的编译/回归结果由根任务统一记录。
- 当前没有浏览器实测的渲染耗时、CPU 或显示帧率基线，不将结构隔离换算成提速百分比。

## 本次实现

`CameraPreview` 成为独立 Yew 组件，拥有 HTTP 帧请求、单请求门闩、帧快照、定时器和镜像状态。父组件仅接收用户的选择、开关、发现设备及云台操作，不接收逐帧消息。状态页的 fps/帧龄使用每秒状态响应，避免为诊断重新引入高频父级更新。

保留同源认证 API、33/250/1000ms 分级轮询、当前帧内 JPEG/框/目标元数据、临时目标与档案隔离和停止入口。关闭/重开使请求版本失效，旧回执不能恢复旧画面；最多一个在途 HTTP 请求。帧中明确为 null 的选中目标不再回退到旧状态轮询中的 key。云台启用参数从子组件当前快照构造，仍交由已有后端验证，不调整运动门限。

`ChatViewport` 使用会话与最后一条 turn_id 识别新内容，不依赖窗口条数。用户距对话底部不超过 48px 时跟随新消息；上翻后保留阅读意图并显示“有新回复 / New reply”入口。点击入口或手动回到底部恢复跟随；切换会话清理旧提示。滚动只修改对话容器的 scrollTop，不调用整页 scroll_into_view。

## 本次活动偏好与档案设置的区别

教师设置中的提示方式明确标为“档案提示方式”。`session_preferences` 为非空对象时，单独显示“本次活动偏好”；结构化提示方式可随界面语言展示，但 `explicit_request` 保持原文与换行，不通过界面文案字典翻译，也不将仅有原话的偏好误标为“一次一步”。

“恢复档案提示方式”仅提交当前 learner.help_style 单字段到已有 settings 端点，由后端清除会话覆盖；忙碌或活动结束时禁用入口。恢复响应后的状态刷新清空偏好后，提示块消失。增加原文与空对象展示逻辑回归，以及 P06/P07 双语任务脚本，合计 27 组，仍为 NOT_RUN。此补充未运行 Cargo 或浏览器，最终编译与设备无关契约回归由根任务统一执行。
